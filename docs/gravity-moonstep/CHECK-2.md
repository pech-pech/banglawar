# CHECK-2: ui.js / game.js / ui.css review (read-only)

Paths relative to pages/gravity-moonstep/src. Ranked by severity.

## Passing
- localStorage: load (game.js:15-27) and save (game.js:28) are both in try/catch. No other storage use in ui.js.
- Bests never downgrade on a normal run: game.js:179-180 only writes when h > prev. Reset (game.js:164) is the only intentional wipe.
- Copy report: game.js:122 sets `webgpu: 'WebGPU output: NOT seen'` in the report extras (also reached from the clipboard-fail modal via ui.showReport).
- Engine determinism: engine.js header says no Date/Math.random; the only Math.random is randSeed (game.js:48-52, UI seed choice) and Date is only used for the daily seed string and UI labels. Engine and gen.js have no hits. Sim steps from fixed DT with logged inputs.
- Listener leaks: none per open. Screens are rebuilt with clear() and listeners die with their nodes; modals and window/canvas listeners are registered once (ui.js:244, game.js:207-243).
- Safe-area: viewport-fit=cover in index.html:3; --sat/--sab/--sal/--sar used on screens, HUD, modals, thumb zone, tide strip.

## Findings
1. MEDIUM, stale-tab downgrade. game.js:28 `save()` writes the whole in-memory store, with no re-read or merge. With two tabs/PWA windows open, the older tab's next save overwrites a higher best from the other tab. Fix: in save(), re-read localStorage and merge (max per best key, max per cnt/medals, union attempts by ts) before setItem; or listen to the `storage` event and merge into store.
2. MEDIUM, 600 ms guard is re-armed by unrelated renders and the focus target is disabled. ui.js:347-349: buttons are disabled for 600 ms from builder time, not from death (overAt, game.js:191, is unused). Any render() of results (closeModal at ui.js:155, e.g. closing the report modal; ui.refresh; returning from records) rebuilds the screen and disables the buttons again for 600 ms, and also rebuilds the Verify chip. The first `[data-focus]` button is disabled when ui.js:139 focuses it, so focus is lost and keyboard users get no focus until after the timer. Fix: pass d.at = performance.now() in ui.open('results') and compute remaining = max(0, 600 - (now - d.at)) when building. Focus the first button inside the timeout callback after enabling. The Verify chip is not gated (harmless).
3. LOW-MED, rebuild-on-modal-close wipes edits. ui.js:155 closeModal calls render(), which re-runs the top builder. The pause seed input (ui.js:293) and title seed input (ui.js:210) lose typed text after an install, confirm or report modal closes. Fix: make closeModal toggle classes only (no builder) unless the data changed (reset already calls ui.refresh at game.js:164).
4. LOW, reduced motion gaps. (a) ui.css:166 `.u-glow{transition:opacity .3s}` has no reduce override. (b) The .u-rm class (which silences .u-tog transitions, ui.css:76) is set only at boot and on the setting (game.js:354, 162); the OS preference change listener (game.js:39-41) recreates fx but never calls ui.setReduced. (c) ui.css:243 media block covers only tchip and stamp. Fix: add `.u-glow` and `.u-tog,.u-tog::after` to the ui.css:243 @media (prefers-reduced-motion:reduce) rule with `transition:none!important`, and call ui.setReduced(reduced()) in the MQ change handler.
5. LOW, safe-area gaps in landscape/notch. `.u-title` zeroes side padding (ui.css:104) and `.u-menu` uses a flat 24px (ui.css:114); `.u-th` uses a flat 72px (ui.css:266); `.u-chip` margin is flat 24px (ui.css:118). None add --sal/--sar, so title content can sit under a landscape notch. Fix: use calc(24px + var(--sal)) / var(--sar) on those. `.u-tchip` top clamp (ui.js:479, min 70) ignores safe-area-top; use 70 + sat.
6. LOW, __proto__ keys. game.js:22-23 copy arbitrary JSON keys into store.set/flags/cnt/medals (plain objects), and seed key "__proto__" makes `store.cnt[seed]` resolve to Object.prototype (game.js:181). best is Object.create(null), so it is fine. Fix: build cnt/medals/flags with Object.create(null) or whitelist set keys, and reject non-number values for cnt/medals.
7. LOW, verify() fallback. game.js:142 falls back to `{tideScale: store.set.tide}` if s.opts is missing. engine.js:142 always sets s.opts, so this is dead today. If it ever triggers, a mid-run tide change from the pause menu would give a false FAIL. Prefer s.opts only.
8. LOW, report accuracy. attemptNo (game.js:69) increments for the boot run and for quit-to-menu, so the report's `attempt` is inflated. Report also embeds inputLog twice (game.js:125 and engine's own field, engine.js:407). Cosmetic.
9. LOW, pointer state. game.js:207-234: if pointercancel/up is never delivered (overlay opened mid-hold), pointerId stays non-null and all later pointerdowns are ignored at game.js:208. onBlock (game.js:171) clears `down` but not pointerId. Fix: set pointerId = null in onBlock.
