# Moonstep code review (engine.js, gen.js, game.js vs CONTRACT + concept D s5)
Scope: only those 3 files + contract + spec. draw.js / audio.js NOT read; their API use is checked against the contract names only.

## CRITICAL
1. game.js:51 + game.js:254. `var ... inZone = false` (line 51) overwrites the hoisted `function inZone(y)` (line 254). `pointerdown` then throws "inZone is not a function", so touch/mouse input never starts a charge. Fix: delete `inZone` from the line-51 var list (it is unused there).

## HIGH
2. gen.js:25 (`mk`). Repel bodies get g0 = 900*sqrt(r/60). The spec and engine.js:53 (`b.g0 || REPEL_G0`) want 600. Repellers push about 50% too hard. Fix: `g0: kind==='repel' ? 600 : 900*Math.sqrt(r/60)`.
3. gen.js:51,79. `prev` is `s.bodies[last]`, which can be a repel body, and the runner can never stand on one (engine.js:271-275 never lands on repel). The next body is then reachability-checked from an unreachable anchor, so the course can be unclimbable. A repel candidate also can never satisfy `landId===cand.id` (probe keeps kind 'repel'), so it burns all 8 tries and takes the 90 px last resort. Fix: anchor `prev` to the last non-repel body, and skip `reachable()` for repel candidates (or probe them as 'still' and only keep the distance rule).
4. game.js:209. Verify replays with the current `store.set.tide`, but the tide can be changed in the pause menu mid-run, giving a false "Replay: FAIL". Fix: `Moonstep.replay(seed, s.log, s.opts)`.

## MEDIUM
5. gen.js:66-80. `place(Math.max(dist,minD))`: when dist0 < minD (big neighbours, minD up to ~200), the 10% shrink has no effect. The 8 tries are identical, and the last resort `place(max(90,minD))` gives the same body, so an unreachable body can ship. Fix: on retry also vary the geometry. Examples: shrink `r` toward 70, or step `ang` toward -90 deg, or re-clamp x toward prev.x. Do this without extra rng draws.
6. gen.js:30-39 with engine.js:353-368. Worst case per body is 8 tries x 120 probes x 600 steps (~576k accel calls). `ensure()` runs inside `tick` and `land`, so this can cause a frame hitch mid-run. Fix: probe maxSteps 300, break when the probe runner is outside both R for more than 0.5 s, and try charges in order [.45,.3,.2,.1,0] so a hit returns sooner. Optionally pre-generate during the newRun load.
7. engine.js:342-345 (`predict`). Per frame while charging it allocates `pts[]`, up to ~15 `{x,y}` objects, and the result object. The contract says "allocation-light". Fix: keep a module-level pool of points and a reusable result, and return `{pts, n}`. The draw side must read `n`, so check this with draw.js.
8. game.js:301-306, 255-262 (+ pointerup at 277). Input is sampled once per rAF. A tap whose down and up both fall between two frames is lost, because `down` flips true then false before `stepOne`. Edges are also quantised to frame time, which hurts the 0.08 s chain window. Fix: queue edges (`pendDown`/`pendUp` counters) and feed each as a one-tick `down` pulse in `stepOne`.
9. engine.js:220-223. A crumble body keeps shrinking while the runner stands on it again (`left` stays true), then drops the runner into air at `dead`. The contract allows "landing during shrink" but is silent on this. At rem near 0, theta speed (`vt/cr`) blows up; `cr` is guarded only at 1e-6 (engine.js:241). Fix: clamp the angular speed (use `max(cr,12)`), or document it. Verify against the draw notch/ring.

## LOW
10. game.js:218-219,45. `store.best` is a plain `{}` keyed by a URL-controlled seed. Seeds like `__proto__` or `constructor` misbehave (`store.best[seed]||0` returns a function). Fix: use `Object.create(null)` or `hasOwnProperty`, and sanitise `store.set.tide` to {0.75,1,1.25} on load (line 23).
11. game.js:102-103. Duplicate `id="mx-s"` (hS and hCh). Fix: give hCh a distinct id.
12. game.js:311 passes `prevSpeed/VMAX` (0..1) to `au('land')`; the contract says `land(vn)`. This is fine only if audio.js expects 0..1 (not verified). Better to pass the normal speed at contact. Fix: read the `vn` at contact, or align the name in audio.js.
13. game.js:33. `Array.prototype.slice.call(arguments,1)` allocates every call, and `au` runs twice per frame (charge, tideLevel). Fix: use fixed-arity `au(fn,a)`. Also `MoonDraw.frame` receives a fresh ui object per frame; reuse one object (game.js:346).
14. gen.js:45, engine.js:149. `s.gen.rng` is a function, so the state is not structuredClone-able. The contract says "plain JSON-able" (JSON.stringify silently drops it). Fix: keep the rng closure in a module WeakMap keyed by `s`, or store the u32 state in `s.gen.a` and advance it manually.
15. Determinism, cross-engine. gen.js:70-75 and engine.js:115-118 use Math.sin/cos/atan2/sqrt (ulp differences between V8/JSC/SpiderMonkey for sin/cos). A replay hash made on one browser could differ on another, and a generation branch could flip. Same-engine replay is fine. Fix: round body x,y to 0.01 in `place()` and document replay as same-engine only. No Date/Math.random/object-iteration hazards found in the engine or gen. game.js uses Date/Math.random only for seed choice, which is OK.
16. gen.js:91. `best` uses `s.height*10` (valid, equals -bestY while positive) rather than the engine's `s.bestY`. They agree; using `s.bestY` is clearer. `s.bodies` is never pruned (about 100 bodies at 1500 m, so O(N) loops stay cheap); findBody relies on index==id, so do not prune without fixing that.
17. engine.js:117,129. Rim speed is `vt/cr`, then multiplied by `rr=cr+9`, so the actual rim speed is `vt*(r+9)/r` (about +11 to +25% over 90). That matches the spec's omega=90/r literally. Confirm it is intended (spec text says "run speed 90 px/s").

## Verified OK (no change)
Hysteresis (engine 79-81, owner reset on land/jump), 35% extra, repel never owner and 100% push, repel solid reflect with REST .35, one bounce then stick, STICK_VN, chain window inclusive 9 ticks and release-while-held-through-landing path, `aimed` via 900-step predict, lost timer reset on rim and in range, tide formula, replay log parity (edges/reverse/cancel on same tick), `release` plus cancel ordering, shared scratch objects (ACC/PR/LV) not re-entered unsafely, fixed-step accumulator with a 30-step cap, `s.bestY` exists in engine state.
