# MixerMad.Sim: port notes

Port of the drive sim in `mixer-mad-v7h.html` (script 6, lines 1590-2870). Pure C#, `double`, fixed step `DT = 1/120`, no Unity or physics-engine dependency.

## Layout
- `Core/World.cs`, `Core/World.Step.cs`: `World.Create(...)`, `World.Step(InputFrame)`, read-only state, events.
- `Core/Level.cs`, `Core/LevelBuilder.cs`: ground polyline, zones, rocks, yard movers; `buildLevel`, `buildYard`, `dailySpec`.
- `Core/Tuning.cs`: the tuning class. `Data/tuning.json` is the one file with every number (PHYS table, per-vehicle values, weather grip, zone grip/drag, crash tolerances, gravity, damping, iterations, probe constants, prop constants).
- `Core/GameData.cs`: `Data/levels.json` (level specs, weather per level, yard specs, daily weather list) and `Data/vehicles.json` (wheel radii, 6 body points, collision probes, per mixer skin). Both are generated by `tools/extract.js`.
- `Core/JsMath.cs`: V8 `Math.hypot` emulation (bit-exact), `Math.sign`, `Math.round`, `a||b`; `Rng` (mulberry32 `seeded()` and `hash()`).
- `Core/MiniJson.cs`: small JSON reader so the library has no package dependency (Unity friendly).

## Update to a newer HTML (v7i)
`node tools/extract.js path/to/mixer-mad-v7i.html --tuning` rewrites levels.json, vehicles.json and the extracted tables in tuning.json (phys, parK, wxGrip, vinfo, g, dt, iter, wheelR, holeMax). Hand-listed constants under `consts` are kept; if the HTML changed one of those (they sit inside step()), edit tuning.json by hand and re-run the parity tests.

## Using it from Unity
Create once: `var tuning = Tuning.FromJson(textAsset1.text); var data = GameData.FromJson(levelsAsset.text, vehiclesAsset.text);`
Per run: `var w = World.Create(tuning, data, new WorldConfig{ Mode, LevelIndex, Vehicle, MixerSkin, Weather, DailyKey, Seed });`
Drive from your own fixed 120 Hz accumulator: `w.Step(new InputFrame(gas, brake))` once per 1/120 s, never with frame time. Blend two consecutive `Points` snapshots for drawing. Drain `w.Events` each frame, then `w.ClearEvents()`.
Events: LevelStart, Crash, Reset, Land (Value 0..1), Checkpoint, FinishLine, Parked, RockHit, Spill, Wheelie, PropHit, ActionStart, ActionEnd.

## Behaviour kept on purpose (do not "fix")
- Crash inside step(): the rest of the drive block still runs; past the flag in the same step the state becomes Stopping.
- Wheel 4 applies its force to all six points before wheel 5 reads its speed; contacts used by the drive code are the previous step's.
- While Crashed there are no physics steps; `crashWait` counts down 0.7 s per tick and the reset step runs in the same tick.
- `propBudget` is per World (JS keeps it for the whole page session).
- Mixer skin (0-3) changes the collider shape and wheel positions; the HTML picks it at random.

## Not ported (presentation or finale, not drive feel)
Pour/fill gauge, excavator dig game, finish toys, crane/dozer/roller finish animations, Combo mode (dig then fill), Fossil Book, result screen, particles, audio. Parked/Done hands over to the 3D layer; `Stars`, `ParTime()`, `RaceStars()` are provided.
