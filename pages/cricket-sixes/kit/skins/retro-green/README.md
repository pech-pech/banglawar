## Fonts
Jersey 10 (headers, buttons, 24 px) and Jersey 15 (body, stats, captions) in `fonts/` (woff2 latin, OFL-1.1, from art/fonts/files/). Tokens `--font-head`, `--font-body`, `--c-font`; scale s/m/l = 14/18/24. One weight only: `font-weight:400` and `font-synthesis:none` (the old faux bold filled the open top of the 6, so "Week 6" read as 8). Header strip numbers use Jersey 10 at 28 px = 1.5 CSS px per font pixel (Jersey 10 pixel = em/18.67, Jersey 15 pixel = em/27, measured from glyph edges), 3 device px per font pixel at dpr 2. Other dpr not verified.
Licence: `fonts/OFL.txt` (OFL-1.1, Copyright 2023 The Soft Type Project Authors). The name tables list no Reserved Font Name, files are the unmodified originals (no patched font, no rename needed). If a glyph patch is made later: save under a new family name and keep OFL.txt. Note: OFL.txt text was fetched from the upstream repo through a summarising tool; compare with https://github.com/scfried/soft-type-jersey/blob/main/OFL.txt before shipping.
Capital I (fixed 2026-11-12): Jersey's I was a bare stem, same as l ("Ives" read "lves"). Two CSS-only faces, "RG Cap I 10" and "RG Cap I 15", map ONLY U+0049 to the serifed I in `fonts/pixelify-sans-700.woff2` (unmodified file, so no OFL rename needed; no glyph patch, no install), with size-adjust 84.4% / 87.5% so its cap height matches Jersey 10 / 15. They sit first in `--font-head` / `--font-body`; all other characters still come from Jersey. Class names and the 14/18/24 scale are unchanged. Checked in Chrome headless at dpr 2: test strip "Ives Icons Ill 1Il |" at 14, 18, 24, 28 px (head) and 13.5, 14, 18, 24 px (body); I and l now read apart and the cap heights line up. The I is a little wider than Jersey's letters and is not on Jersey's exact pixel grid (scaled), visible only close up. Not checked on a device or other dpr. A page that sets `font-family: "Jersey 15"` directly (not through the tokens) does not get the fix.
Names font (changed 2026-11-12, QA h-m0 H1): names are back on the Jersey stacks; Pixelify Sans is no longer used for names in the skin. Its capital B read as G ("Brackwell" read "Grackwell", "Brandt" "Grandt") and C as O ("Corvale" read "Oorvale"), and it was only there for capital I, which the RG Cap I faces now fix. Row titles (`.c-row__title > span:first-child`) and coach chips (`.cp-name > .c-chip__name`) use `--font-body` (RG Cap I 15, Jersey 15); sheet titles (`.c-sheet__title`) use `--font-head` (RG Cap I 10, Jersey 10), as before L3. Same classes, same sizes. The "Pixelify Sans" @font-face is kept only because `mockups/first-session/fs.css` `.name` still asks for it (not changed here; it still shows the B/G problem). Checked in Chrome headless (Playwright) at dpr 2: strip "Brackwell Brandt Dunmore Okoro Corvale Ives Ill 1Il" at 13.5/14/18/20/24/28 px (rows), 14-28 (chips), 18-28 (sheet titles): B, C, D, O and I/l read apart at every size. In Jersey 10 (sheet titles) D and O are closer (both squared; D has square left corners, O cut ones), still distinct at 18 px and up. Not checked on a device or other dpr.
Pixelify Sans licence: `fonts/OFL-pixelify-sans.txt` now matches upstream https://github.com/eifetx/Pixelify-Sans/blob/main/OFL.txt byte for byte (fetched 2026-11-12; the only difference was the licence URL line). `fonts/OFL.txt` (Jersey) was also compared with upstream and is identical, so the "compare before shipping" note above is done.

## Checks (measured in proof, Chrome headless; not on device)
- Label contrast (WCAG): dark on chalk 12.98, light on pressed 5.74, white on primary 6.39, chalk on primary pressed 8.79 (all >= 4.5).
- Pressed clearly different: dark inset fill, no drop edge, light label; primary pressed is a darker green again (see stills).

- Tap: kit minimums unchanged (56 px); preview script found no button under 56 in either dimension.
