# Slice A: Starfall skin (play-field renderer) - change note
Files: `src/parts/draw.js` (rewritten world renderer), `src/test/skin-harness.html` + `src/test/skin-shots.js` (new), shots `src/review/shots-beta/skin-*.png`. No commit. Choices labelled admin default.

## What PL.draw does now (world only; no HUD, no pad)
Order: PL.Vfx.drawBack (art backdrop top-anchored so the dome shows; procedural aurora bars follow the art's dome) -> moonstone platforms (PL.Assets.drawPlatform, multiply-toned lavender) -> lanterns (code, picked clear of start/exit/hazards) -> crumble ledges (art + 3 crack stages from state.crumbleS timer, shake, fade) -> exit portal art (glow left to Vfx) -> gates (code: teal-white ribbon, waves, chevrons flowing along the pass dir, end orbs) -> spikes (art rotated to their wall, coral halo) -> crushers (PL.crusherRect, art head, coral lane that heats toward the stroke end) -> hero -> PL.Vfx.drawFront.
Hero: body by pose (idle, land, hurt, win; fall/dive = idle stretched by Vfx.heroDeform, dive extra), box-sized (2*HALF*1.18), feet eased to gravity, shadow, blink lids, idle bob, win vanish.
Hit-rect overlay: Tweak `SKIN_DEBUG`=1, `PL.Skin.setDebug(true)` or `hud.debug`. Shot: skin-*-debug.png (drawn art sits inside the rects).
Quality: Tweak `FX_QUALITY` (0 auto,1 full,2 lite,3 off) or `hud.quality`; reduced motion: `hud.reduced`. Missing art => Starfall code shapes (coral #ff7a6b from PL.UI.C when present). Whole frame is try/catch wrapped.
Removed: paper/grid, swipe strip tint, swipe hint, plumbline, old dust.

## Changes other parts must know
- `PL.draw(ctx, view, frame, state, hud)` signature unchanged, but it no longer draws the HUD, toast, tuning panel, teach banner or complete screen. Old code kept as `PL.drawHudLegacy` (runs only if `hud.legacyHud` is true). `PL.BTN`, `PL.menuLayout`, `PL.drawMenu`, `PL.tuningLayout`, `PL.predictPath` kept as they were.
- draw.js owns the Vfx/Light lifecycle: lazy `PL.Vfx.init/resize`, `setRoom` on room change, `setBackdrop`, `update(dt, events, state, g)` each draw. Call `PL.Vfx.drawOverlay` (star wipe) yourself above the HUD.
- Events: sim runs up to 5 steps/frame and clears `state.events` each step, so draw.js wraps `PL.step` (only for the live state) to collect them. If ui.js passes `hud.events` (array of strings) that wins.
- draw.js calls `PL.Assets.load()` if nobody has (same-folder files). inline.py part order must include assets, light, vfx (and uikit before draw for tokens, optional) before draw.js.
- Hacks: sets `PL.Vfx._V.room` to a gates-less clone (skin draws gates; Vfx's gate chevrons ran along the long axis, not the pass dir), `PL.Light._S.dome` and `_S.bloomAmt=0.55`.

## Beta polish + performance pass (2026-11-19) - draw.js, light.js, vfx.js, tests
All choices "admin default". No install, no spend, no commit.

Targets (full < 8, lite < 4) met on this metric. With the raster flush included (`FLUSH=1`, headless software raster at 4x throttle) full is still ~150 ms (before ~190): the software rasteriser filling a full-screen dpr-2 backdrop dominates and is not representative of a GPU canvas; true device frame time is NOT measured.
**What changed:** static things baked once per room+scale into small tiles (one canvas per wall, spike row, gate; not one room-sized canvas): platforms (brick lines subtler, crisp gold edges on exposed faces, brass corner brackets, soft rim light cut away near hazards), spike crystals + tight coral ellipse glow, gate bodies + brass star caps; floor reflection + violet floor glow under the room (fills the empty band on tall screens). Far light (4 shafts, now teal/violet, about half the old alpha) baked into the backdrop; a baked dark scrim keeps the room centre darker than platforms. Aurora = 3 pre-rendered strips that slide/breathe/shimmer (no per-frame bars). Bloom 1/6 res rebuilt every 2nd frame; glow pools, hero disc and bloom now drawn BEFORE hazards (`Vfx.drawGlow`), so light never washes a hazard; no ctx.filter, shadowBlur or getImageData, per-frame gradients removed (sprites instead).
**New public options (the three hacks are gone):** `Vfx.setBackdrop(far, near, {dome})`, `Vfx.setDome(d)`, `Vfx.setBloom(a)` (also `init(...,{bloom})`), `Vfx.setRimBaked(b)`, `Vfx.setRoom(room, {skinGates, spikeScale})` (skinGates: Vfx skips its gates; spikeScale: glints follow the 1.6x crystals), `Vfx.drawGlow(ctx,cam)`, `Vfx.drawHeroTrail(ctx,cam)`, `Vfx.quality()`, `Vfx.clock()`; `Light.setDome/setBloom/setRimBaked/setShaftAlpha/clipHazards/driftVec/drawGlow`. Vfx's own gate chevrons now slide along the pass direction (not the long axis). `Vfx.drawFront` still works alone (legacy callers: rim + glow drawn there when drawGlow was not called).
**Look:** hero body 1.5x the box (feet stay on the box edge), gold glow disc, tapered teal flame ribbon from the last ~14 positions (idle: short rising flame; fast: longer, capped, reduced-motion: short and still) plus the existing spark particles. Spike crystals 1.6x the hit rect height, growing away from the wall. Brass lanterns drawn in code (ring, cap, glass, flame, base, wall arm) hanging toward gravity on a damped pendulum, warm flicker. Crusher: coral lane kept, brass piston rod + wall flange, slam shudder + 16 dust puffs + shake. Debug (`SKIN_DEBUG`, `PL.Skin.setDebug`) shows true hit rects.
**Tests:** `src/test/vfx.test.js` 16 pass (new test for the options). `skin-shots.js` passes at 3 sizes, 0 draw errors.
